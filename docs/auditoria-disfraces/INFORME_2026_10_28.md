## Método y límites

Se consultaron rangos acotados al tamaño actual: `disfraces!A1:B995` y
`categorias_disfraces!A1:B999`. Se validó ID de columna A contra registro_json,
IDs únicos, categorías y estructura. El snapshot privado no se publica en Git.

Duplicados: coincidencia del nombre completo, ignorando mayúsculas, tildes y
espacios repetidos. No se mezclaron variantes como Alicia / Alicia 2, talles,
ediciones o nombres parecidos. Se conservaron los nombres exactos en el CSV.

Categorías: se cruzaron categoryId y categoryIds con la pestaña real y se
revisó el respaldo por nombre cuando no hay categoryId, como hace el backend.
En Niños se comprobaron ID principal válido, coincidencia del texto con el ID,
presencia del principal en categoryIds, ausencia de IDs inexistentes y ausencia
de combinación con Hombres/Mujeres. Los 74 registros cumplen esos controles.
No se dedujo edad/talle de fotografías ni se inventó una clasificación semántica.

Fotos: se descargaron en memoria las **414 URLs image existentes**, solo GET,
sin transformaciones nuevas, subidas ni borrados. Se midieron sus dimensiones
reales con Pillow y se contrastó photoWidth cuando existía. Se audita **ancho**
menor a 600, manteniendo el criterio del importador; una foto vertical puede
tener alto mayor a 600 y ancho insuficiente. No se midieron thumbnails de 160 px
como si fueran fotos principales. En los 134 registros sin image, photoWidth
se informa como dato de origen; no se inventa ancho publicado ni se confunde
la ausencia de publicación con una URL rota.

El resultado refleja la lectura de esa hora. Los 134 productos sin foto
publicada están inactivos. De las 26 fotos publicadas de menos de 600 px,
14 corresponden a fichas activas y 12 a inactivas. Toda eventual corrección necesita otra tarea y
autorización: este PR contiene únicamente el CSV y este informe.
